# Форматы вывода

## Общий формат

```
## Проверка: [утверждение]

### Разметка

| # | Утверждение | Тип | Модальность | Влияние | Релев. | Спорность | Провер. | Решение |
|---|-------------|-----|-------------|---------|--------|-----------|---------|---------|
| 1 | [текст] | число | факт | 3 | 3 | 2 | 3 | проверить |
| 2 | [текст] | поведение | факт | 2 | 3 | 3 | 3 | проверить |
| 3 | [текст] | признак | мнение | 1 | 2 | — | — | метка |
| 4 | [текст] | смешанное: число + связь-причина | факт | 3 | 3 | 3 | 3 | проверить по частям |
| 5 | [текст] | число | факт | 3 | 3 | 2 | 1 | НЕ ПРОВЕРЕНО: [причина] |
| 6 | [текст] | событие | факт | 1 | 1 | 1 | 3 | пропустить |

[Если целей нет, колонка «Релев.» убирается. Если утверждение одно, таблица из одной строки, оценки всё равно ставятся]

---

### Вердикт: [по модальности, см. ниже]

### Определённость: [██████████] XX%

**Из чего складывается:**
- Качество источников: [высокое/среднее/низкое] — [по карточкам: типы, флаги]
- Независимость: [высокая/средняя/низкая] — [сколько первоисточников за числом]
- Консенсус: [полный/частичный/нет] — [кратко почему]

---

### Сверка с указанным источником

[Только если у утверждения была ссылка]
- Источник: [название, тип]
- Говорит: [дословно]
- Совпадает с утверждением: [да / нет, в чём расхождение: число, объект, период, определение]

---

### Источники (по типу)

1. **[Название]** — [статистика / исследование / научная работа / эксперт / компания о себе / СМИ / блог]
   - Говорит: [суть]
   - Ссылка: [URL], [дата]
   - Карточка: первоисточник [есть / пересказ / пейвол]; автор [человек / организация / нет]; мотивация [нейтральный / заинтересован]; выборка [N, кто, метод — для исследований]; дата [ок / старше 2 лет, могло измениться]
   - Для СМИ: ссылается на [первоисточник], дошли до него [да / нет]

2. **[Название]** — [тип]
   ...

---

### Анализ

**Совпадения:** [что подтвердилось]
**Расхождения:** [где не согласны]
**Пробелы:** [что не проверено]

---

### ⚠️ Предупреждения

[Только если есть: BIAS, ЭХО, УСТАРЕВШЕЕ, НЕДОСТАТОЧНО, СТЫК, ПЕРЕНОС, ЗАЯВЛЕНО, ОДИН СЛУЧАЙ, НЕ ПРОВЕРЕНО]

---

### Итог

[1-2 предложения: что делать с информацией]
```

## Дополнения по типу

### Число

После разметки добавить карточку числа:

```
### Карточка числа

| Поле | Значение в утверждении | В источнике |
|------|------------------------|-------------|
| Значение и единица | | |
| Объект (с границей) | | |
| Период, база сравнения | | |
| Знаменатель | | |
| Определение метрики | | |
| Происхождение | [первичный замер / вендорская оценка / самоотчёт / кейс агентства / опрос / расчёт автора] | |
```

Несовпадение в любой строке — вердикт ЧАСТИЧНО или ОПРОВЕРГНУТО с указанием строки. Карточка заполняется при любом типе утверждения, если в нём есть величина.

### Поведение

```
### Карточка поведения

| Поле | В утверждении | В источнике |
|------|---------------|-------------|
| Кто (сегмент, граница) | | |
| Что делает, как часто | | |
| Контекст (где, когда, условия) | | |
| Происхождение | [наблюдённое / заявленное / единичный случай] | |
| Независимых источников за паттерном | | |
```

Заявленное поведение получает вердикт не выше ЧАСТИЧНО, если утверждение сформулировано как наблюдённое. Единичный случай — НЕОПРЕДЕЛЁННО с флагом ОДИН СЛУЧАЙ. Если есть доля, ниже карточка числа.

### Наличие

```
### Полнота поиска

- Где искали: [источники, базы]
- Сколько нашли: [N]
- Что могли пропустить: [закрытые базы, языки, период]
```

Для утверждения «нет» вердикт ПОДТВЕРЖДЕНО только при описанной выборке.

### Событие

```
### Событие

- Дата: [в утверждении] / [в первичном источнике]
- Участники: 
- Документ или первичное сообщение: [URL]
```

### Связь

```
### Связь

- Конец A: [утверждение, тип, вердикт]
- Конец B: [утверждение, тип, вердикт]
- Характер в утверждении: [сравнение / часть–целое / последовательность / корреляция / причина / тождество]
- Характер по источникам: [тот же / другой]
- Кто утверждает связь: [автор / цитируемый эксперт / источник]
```

Для сравнения: таблица совпадения объекта, периода, единицы, знаменателя у концов. Для причины: что ещё менялось в тот же период.

## Блок feedback (режим `/fact-check:feedback`)

```
> **Фактчек · ВЕРДИКТ · флаг ФЛАГ**
> **Утверждение:** «дословно из текста»
> **Расхождение:** одно-два предложения, в чём проблема
> **Найдено:** альтернативная цифра или формулировка — [источник](URL) (тип источника, дата)
> **Рекомендация:** что делать с утверждением: оставить, убрать, переформулировать, использовать с оговоркой; на какой источник или число опираться вместо него
```

Пять строк, одно поле на строку, вердикт и флаги в заголовке блока. Рекомендация обязательна в каждом блоке и пишется одним-двумя предложениями в повелительной форме: «убрать», «оставить с оговоркой про квартал», «опираться на отчётность Delta за год, не на квартал», «заменить на 43% пассажирской выручки». Без рекомендации замечание не закрыто. Флагов нет — заголовок `**Фактчек · ВЕРДИКТ**`. Одно замечание — один блок. Несколько замечаний к одному месту — несколько блоков подряд, между ними пустая строка. Блок ставится **непосредственно под строкой с утверждением**: если утверждение — пункт списка, блок вкладывается под этот пункт с отступом в два пробела, не под весь список; если абзац — под абзацем. Сплошной текст внутри блока запрещён: читатель должен с первого взгляда отличать цитату от замечания.

Пример под пунктом списка:

```
- **Премиум даёт уже 43% пассажирской выручки Delta** (было 35% в 2019) — источник: [Reuters](URL)
  > **Фактчек · ПОДТВЕРЖДЕНО · флаг СТЫК**
  > **Утверждение:** «Премиум даёт уже 43% пассажирской выручки Delta (было 35% в 2019)»
  > **Расхождение:** обе цифры сходятся, период — июньский квартал 2025. Строкой выше в том же списке «с 45% до >50%» считается от билетной выручки за Q4'25: два числа измеряют разное, из списка это не читается.
  > **Найдено:** 43% пассажирской выручки за июньский квартал против 35% в 2019 — [Fast Company по Reuters](URL) (СМИ, 2025)
  > **Рекомендация:** оставить, но развести с соседней строкой: указать у обеих цифр знаменатель и квартал, либо убрать одну из двух. Для презентации опираться на годовую отчётность Delta, не на квартал.
```

В конец файла раздел `## Фактчек <дата>`: три счётчика (выделено / проверено / с замечанием, из них опровергнуто) и список «Не проверено по лимиту».

## Блок biases (режим `/fact-check:biases`)

Под абзацем с выводом, только если искажение есть:

```
> **Искажение · ПОДМЕНА ВОПРОСА**
> **Утверждение:** «дословно из текста»
> **Проблема:** в чём вывод не следует из данных, одно-три предложения
```

Типы: базовый процент, иллюзорная закономерность, ошибка выжившего, смешение причины и следствия, причинность задним числом, лжеобъяснение, авторитет вместо данных, WYSIATI, подмена вопроса, предвзятость подтверждения, иллюзия достоверности через детали, чужая аудитория. Список с вопросами в `references/biases.md`.

Пример:

```
**Разрыв спрос/предложение.** 76–78% россиян хотят есть рыбу чаще, но 70% не знают как. Рыба = сложно, долго, пахнет, дорого. Решение — convenience-формат.

> **Искажение · ЛЖЕОБЪЯСНЕНИЕ**
> **Утверждение:** «Потребитель не отказывается от рыбы, он отказывается её готовить»
> **Проблема:** формулировка объясняет любой исход: рост полуфабрикатов подтверждает её, падение объяснили бы ценой. Вывод ничего не запрещает, поэтому его нельзя проверить. Чтобы вывод стоял, нужен замер: доля тех, кто перестал покупать сырую рыбу, но покупает полуфабрикаты.
```

Второй пример, чужая аудитория:

```
**Ценовая стратегия.** Потребители переключаются на бюджетную рыбу (минтай +20%). Продукты с добавленной стоимостью позволяют увеличить маржинальность при доступной цене за порцию.

> **Искажение · ЧУЖАЯ АУДИТОРИЯ**
> **Утверждение:** «Потребители переключаются на бюджетную рыбу (минтай +20%)»
> **Проблема:** цель исследования — покупатели полуфабрикатов и готовой еды под бренды UNIFROST. Рост минтая замерен по всей рознице, в нём сидят покупатели сырой рыбы, которые полуфабрикаты не берут. Переносить их ценовое поведение на целевой сегмент нельзя без данных о том, кто именно покупает минтай.
```

В конец файла раздел `## Фактчек и искажения <дата>`: счётчики фактчека и число искажений по типам.

## Блок specific (режим `/fact-check:specific`)

По одному блоку на каждое присланное утверждение, в чат:

```
### [N]. «[утверждение дословно]»

[тип] / [модальность] · **ВЕРДИКТ** · определённость XX% · флаги: [если есть]

**По указанному источнику:** [совпадает / расходится в: … / источник не указан]
**Найдено:** [что говорят первоисточники, с числами, объектом, периодом]
**Источники:**
- [Название] — [тип], [дата] — [URL]
- [Название] — [тип], [дата] — [URL]
**Итог:** [одно предложение: как использовать утверждение]
```

Для смешанного утверждения внутри блока подпункты по частям с вердиктом каждой и общим вердиктом по слабейшей. Для мнения: карта позиций в две строки вместо «Найдено». Для прогноза: автор, методология, консенсус в две-три строки.

## Смешанное утверждение

Одна запись, внутри разбор по частям. Части нумеруются, каждая получает тип и вердикт, общий вердикт по слабейшей проверяемой части:

```
### Утверждение: «[полный текст]» — смешанное: число + число + связь-причина / факт

**Часть 1** «[фрагмент]» — число / факт
→ Вердикт: 
→ [Краткий анализ, карточка числа при необходимости]

**Часть 2** «[фрагмент]» — число / факт
→ Вердикт: 
→ [Краткий анализ]

**Часть 3** «[фрагмент]» — связь-причина / факт
→ Вердикт: 
→ [Кто утверждает связь, что ещё менялось]

**Часть 4** «[фрагмент]» — признак / мнение
→ Не проверяется. [Кто так говорит]

→ **Общий вердикт:** [по слабейшей проверяемой части]
→ [Что из исходной фразы выдерживает проверку, а что нет]
```

## Несколько утверждений

Если на входе текст с несколькими независимыми утверждениями, после общей таблицы разметки идёт блок по каждому проверяемому утверждению в том же формате, затем итог по тексту целиком.
